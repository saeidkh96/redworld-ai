# v1.2.3 — Performance & Runtime Optimization

RedWorld AI v1.2.3 focuses on simulation performance and runtime scalability while preserving the behavior introduced by Autonomous Living World.

## Highlights

- incremental accounting balance indexes
- constant-time ledger balance lookup
- indexed social-relationship lookup
- lower-overhead economy metric aggregation
- cached geographic shortest paths
- automatic path-cache invalidation when geography changes
- preserved accounting journal and audit history
- preserved deterministic simulation behavior
- preserved 1,500 citizens
- preserved 40 businesses
- preserved 4 civic institutions
- preserved 1,544 autonomous agents

## Performance

The original simulation baseline was approximately:

- `0.70 s/tick`
- `1.4 steps/s`

After the v1.2.3 optimization work, representative runtime measurements reached approximately:

- `0.039 s/tick`
- `25–28 steps/s`

This represents roughly an 18× simulation throughput improvement on the development machine.

## Optimization areas

### Accounting

Ledger balances are now maintained incrementally instead of recomputing balances by scanning the complete journal history for every account query.

### Social graph

Citizen relationship retrieval now uses a per-citizen index instead of scanning every relationship in the graph.

### Economy metrics

Economy aggregation uses raw Decimal account balances internally and creates Money values only for the final aggregate metrics.

### Geography

Repeated shortest-path requests are cached. Cached routes are stored immutably and returned as independent lists so citizen movement cannot mutate shared route state.

The route cache is invalidated whenever locations or travel connections change.
